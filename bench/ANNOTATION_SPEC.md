# Xcup 动作真值标注规范 v1

本规范定义 Xcup 评测基准（bench/）所使用的人工真值（ground truth）标注方式。
所有 `bench/gt/*.csv` 必须符合本规范。修改规范必须递增版本号，并在文件头
`spec_version=` 中记录，否则新旧真值不可混用。

---

## 0. 适用范围与总原则

**真值回答的唯一问题是：此刻飞机杯的马达「该不该转」。**

真值不是"视频里有没有拍到动作"，也不是"模型应该输出哪一类"，而是**产品意图**：
一个理想的系统在这一刻应该让马达处于什么状态。所有歧义都回到这一条来裁决。

推论（重要）：

- 不按模态标注。不存在"视频真值"和"音频真值"，只有一条真值时间线。
- 镜头切走不等于动作停止。详见 §3。
- 真值的时间分辨率受流水线物理能力约束。系统的融合 tick 是 500ms、平滑窗 3s、
  蓝牙最短驻留 2000ms，因此标注比 1 秒更细的段没有意义（§4）。

## 1. 产出物与文件格式

每个视频对应一个 CSV：`bench/gt/<video_id>.csv`（例：`v01.csv`）。

```
# xcup-gt spec_version=1
# video_id=v01
# file_name=v01.mp4
# file_size=1873221120
# duration_ms=1804233
# frame_rate=29.97
# annotator=tingfu
# created_at=2026-09-28
# pass=3
start_ms,end_ms,label,note
0,12400,plot,
12400,58900,oral,
58900,61200,exclude,黑屏过场
61200,145000,sex,
```

格式约束：

| 项 | 规则 |
|---|---|
| 注释行 | 以 `#` 开头，位于表头之前，`key=value` 形式；读取脚本用 `comment='#'` 跳过 |
| 时间单位 | 整数毫秒，从视频第 0ms 起算 |
| 区间语义 | **半开区间 `[start_ms, end_ms)`**，避免边界毫秒被两段重复计数 |
| 首尾相接 | 必须 `end_ms[i] == start_ms[i+1]`，**不允许空隙、不允许重叠** |
| 起止 | 第一行 `start_ms == 0`；最后一行 `end_ms == duration_ms` |
| 排序 | 按 `start_ms` 严格升序 |
| 相邻段 | 相邻两段的 `label` 不得相同（同标签必须合并成一段） |
| note | 可为空；含逗号或引号时按 RFC4180 加双引号转义 |
| 文件指纹 | `file_name` + `file_size` + `duration_ms` 三项用于确认真值与视频没有错配 |

> **为什么必须无缝覆盖全片**：逐秒准确率的分母是"全片可评测时长"。
> 如果允许空隙，未标注区间到底算什么就成了脚本的隐式假设，指标会悄悄失真。
> 不确定的区间必须显式标 `exclude`，不能留空。

## 2. 标签定义

共 5 个标签。前三个与模型的三分类一一对应（`0 normal_plot / 1 oral / 2 sex`）。

### `plot` — 剧情 / 非成人动作（期望：不转）

对话、铺垫、换场、穿脱衣、走动、独白、采访、无成人内容的亲密（拥抱、纯接吻）、
片头片尾、预告。

### `oral` — 口交（期望：转）

口部与生殖器接触且动作进行中。包含全身机位与头肩特写两种（对应训练集的
`000 女性全身口` / `001 女性特写口`，真值不区分）。

### `sex` — 性交 / 抽插（期望：转）

含插入且有抽插动作。任意体位（传教士 / 后入 / 骑乘 / 站立）、任意人数。

### `other_adult` — 成人动作但不属于上述两类（期望：**策略位**）

手交、足交、乳交、单人自慰、纯爱抚 / 前戏无插入、道具、以及其他明显是成人内容
但既不是口交也不是抽插的段落。

> **为什么要单列这一类**：模型只有 3 类，训练集里没有这些内容。如果把它们
> 塞进 `plot`，模型判"转"会被算成误报；塞进 `sex`，模型判"不转"会被算成漏报。
> 两种做法都在用一个模型没学过的东西惩罚它，指标失去指导意义。
>
> 因此：**单独标注、单独统计**。默认从准确率与延迟中剔除，但报告里必须打印
> "`other_adult` 时长占比"——这个数字本身就是产品结论：如果真实视频里有 15%
> 的时间落在模型的能力空洞里，那下一步该做的是扩类别，而不是继续调阈值。

策略位由 `bench/configs/*.json` 的 `other_adult_policy` 决定，三选一：

- `exclude`（默认）：不计入准确率/延迟，单独报告占比
- `do`：视为期望转（当你决定产品上这些场景也该转）
- `noise`：视为期望不转

标注者**不做这个决定**，只负责如实标出来。

### `exclude` — 不可评测（期望：无）

- 黑屏、纯色转场、制作方 logo、马赛克检查画面、纯字幕板
- 画面与声音都无法判断的段落
- 视频损坏、卡顿、花屏

`exclude` 不是"懒得标"的出口。占比超过 10% 的视频不适合进基准，换片。

## 3. 切换点（边界）定义 —— 本规范最重要的一节

延迟指标的分母就是切换点。切换点标错，延迟数字全部作废。

### 3.1 基本定义

切换点取**动作实际发生变化的那一帧**，不是"你看清楚了"的那一帧，也不是
"声音开始像了"的那一帧。

- `plot → oral`：口部**首次接触**生殖器的那一帧
- `plot → sex`：**首次插入**的那一帧（若插入被遮挡，取抽插动作明确开始的第一帧）
- `oral/sex → plot`：动作**最后一次往复结束**的那一帧（不是拔出后两人说话的那一帧）
- `oral ↔ sex`：切换的那一帧

### 3.2 镜头切走 ≠ 动作停止

**判据是动作是否在进行，不是画面是否拍到。**

| 情形 | 处理 |
|---|---|
| 动作进行中，镜头切到脸部特写 / 空镜 / 对方反应，**< 3s** 后切回 | 维持原标签，**不打断** |
| 动作进行中，镜头切走 **≥ 3s** 且期间无任何动作证据（声音也停） | 切为 `plot` |
| 剧情段中插入回忆/幻想的成人画面（观众此刻正在看该内容） | 按画面内容标 `oral`/`sex` |
| 画面黑屏但声音明确持续 | 维持原标签（按声音连续性） |

3s 这个阈值不是随手定的：流水线自身的反应时间就是 2s 新鲜度窗 + 2.75s 视频窗，
把一个 2s 的镜头切走标成"应该停转"，本身就是系统物理上做不到的要求。

### 3.3 动作中的停顿

体位转换、调整姿势、短暂喘息导致动作暂停：

| 停顿时长 | 处理 |
|---|---|
| **< 5s** | 维持原标签，不打断 |
| **≥ 5s** | 切为 `plot`（或 `other_adult`，按停顿期间实际内容） |

5s 的依据：蓝牙状态机停一次再启动，最快也要
`stopStable 1000ms + minDuration 2000ms + sendInterval 1600ms ≈ 4.6s`
（见 `VideoProcessActivity.java:131-132` 与 do→Noise 的 1000ms 稳定要求）。
把 4s 的停顿标成"该停转"，等于要求系统做一件它按设计就不会做的事。

### 3.4 精度分级（省力关键）

不同类型的边界对指标的影响完全不同，**不要在不重要的边界上花时间**：

| 边界类型 | 精度要求 | 原因 |
|---|---|---|
| `plot ↔ oral`，`plot ↔ sex`，`plot ↔ other_adult` | **±300ms** | 跨越 转/不转，直接决定延迟指标 |
| `oral ↔ sex` | ±1s 即可 | 两者都映射为"转"，不影响二值指标，仅用于细类诊断 |
| `exclude` 的起止 | ±1s 即可 | 该段本来就被剔除 |

## 4. 时间精度与最短段长

| 项 | 值 | 依据 |
|---|---|---|
| 关键边界精度 | ±300ms | 单人可复现的量级；小于流水线 500ms tick |
| 护带（guard band） | 边界前后各 500ms | 由**指标脚本**自动剔除出准确率计算，标注者不用管 |
| 最短段长 | **≥ 1000ms** | 平滑窗 3s + tick 500ms，系统不可能响应更短的段 |
| 短段处理 | < 1000ms 的段必须合并进相邻段，或整段标 `exclude` | |

护带只影响**准确率**；**延迟**始终用未加护带的原始切换点。

遇到没列出的情形，先按 §0 的总原则判断，然后**把新案例补进这张表**并递增规范版本。

| 场景 | 裁决 | 备注 |
|---|---|---|
| 纯接吻、拥抱、抚摸（着衣） | `plot` | |
| 脱衣、口爱前的铺垫 | `plot` | 到首次接触才切 |
| 爱抚（裸露，无插入无口交） | `other_adult` | |
| 手交 / 足交 / 乳交 | `other_adult` | |
| 单人自慰 | `other_adult` | |
| 使用道具（无插入） | `other_adult` | |
| 插入中静止不动（无抽插）> 5s | `other_adult` | 声音与画面都无往复运动 |
| 群交 / 多人 | `sex` | |
| 69 / 口交与抽插同时 | 取**主要动作**；难分时取 `sex` | 二者同为"转"，不影响二值指标 |
| 快速交替 oral / sex（各段 < 5s） | 合并成一段，取占比大的标签 | 都是"转" |
| 采访 / 幕后花絮 | `plot` | |
| 片头 AV 预告混剪（含成人画面） | 按画面实际内容逐段标 | 常有大量短段，若 < 1s 则整段 `exclude` |
| 打码严重完全看不清，但声音明确 | 按声音标 | |

| 画面在做爱，声音是 BGM 无人声 | 按**画面**标 | 同上 |
| 慢放 / 回放镜头（重复展示同一动作） | 按画面内容标 | 观众此刻在看该动作 |
| 分屏 / 画中画（一半剧情一半动作） | 按主画面；主画面不明确则 `exclude` | |

## 6. 标注流程（三遍法）

一遍标完既慢又不准。分三遍，总耗时约 1.5× 片长。

### Pass 1 — 粗标（1.5~2× 倍速）

用 `bench/tools/labeler.html`，倍速播放，只在明显切换处按标签键打点。
**不追求精度**，允许差 1-2 秒。目标是把全片的段结构搭出来。

### Pass 2 — 精修（逐帧）

用 `[` / `]` 依次跳到每个切换点，暂停，用 `,` / `.` 逐帧前后确认，
用 `Shift+,` / `Shift+.` 把边界挪到准确的那一帧。
只精修 §3.4 里要求 ±300ms 的那类边界，`oral↔sex` 跳过。

### Pass 3 — 自查

看标注器右侧的统计与告警面板，逐条清掉（§7）。

## 7. 自检清单

导出前必须全部通过：

- [ ] 无 `< 1000ms` 的段（标注器会标红）
- [ ] 相邻段标签不相同
- [ ] 首段 `start_ms == 0`，末段 `end_ms == duration_ms`
- [ ] `exclude` 占比 < 10%
- [ ] 切换点（`do ↔ noise` 方向）数量 ≥ 5，否则该视频对延迟指标贡献太小
- [ ] 各标签时长占比与你对这部片子的直觉相符（`plot` 占 90% 通常意味着漏标）
- [ ] 文件头 `annotator` / `frame_rate` / `spec_version` 已填
- [ ] 随机抽 3 个边界回放确认，误差在 ±300ms 内

## 8. 一致性校验

单人标注无法做标注者间一致性（IAA），改用**自一致性**：

1. 全部标完后，**间隔 ≥ 5 天**，重新独立标注其中 1 个视频（不看旧结果）
2. 对比两次结果：
   - 关键切换点的时间差中位数应 **< 300ms**
   - 逐秒（100ms 栅格）二值一致率应 **> 97%**
3. 不达标 ⇒ 规范有歧义，找出分歧点补进 §5 裁决表，递增版本号，重标受影响视频

这一步的产出是你的**指标噪声底**：如果自一致率只有 95%，那准确率从 93% 调到 95%
的改动就是不可信的。没有这个数字，后面所有 A/B 对比都无法判断显著性。

## 9. 派生映射（供指标脚本使用）

| label | 期望马达 | 计入准确率 | 计入延迟 | 单独报告 |
|---|---|---|---|---|
| `plot` | 不转 | ✓ | ✓ | |
| `oral` | 转 | ✓ | ✓ | 细类召回 |
| `sex` | 转 | ✓ | ✓ | 细类召回 |
| `other_adult` | 由 `other_adult_policy` 决定，默认剔除 | 默认 ✗ | 默认 ✗ | 时长占比 |
| `exclude` | 无 | ✗ | ✗ | 时长占比 |
| 边界 ±500ms 护带 | 无 | ✗ | ✓（用原始边界） | |
| 片头 0~3000ms | 无 | ✗ | ✗ | 模型窗口预热期 |

最后一行的依据：视频窗口要 12 帧 × 250ms = 2.75s 才填满，音频有 2000ms 死区，
这段时间系统结构上无法输出任何判定，不该计入准确率。

## 10. 视频文件准备

- 标注用的视频与感知层 dump 用的视频**必须是同一个文件**（同一 `file_size`）。
- 浏览器放不出来（H.265/HEVC 等）时，转码成 H.264 再标：
  ```bash
  ffmpeg -i in.mp4 -c:v libx264 -crf 20 -c:a aac -movflags +faststart out.mp4
  ```
  **不得使用 `-ss` / `-t` 裁剪**，否则时间轴整体偏移，真值全部失效。
  转码后以转码文件为准（`file_name`/`file_size` 记转码后的），dump 也用同一份。
- 建议片长 20~40 分钟，且每片至少 5 个 `do ↔ noise` 切换点。
- **提前划分 dev / test**：dev 用于调参，test 只在最终验证时跑一次。
  在文件头加 `# split=dev` 或 `# split=test`。
